\subsection{Correspondence between symbols and code}

In Listing~\ref{lst:model}, lines 69--134 check the inputs, 144--185 set the parameters, 187--201 create the model and variables, 203--208 set the objective, 210--252 add the constraints, 254--260 solve, and 262--286 read the status, gap and solution only when one exists. Sets and parameters keep their names; \texttt{mu}, \texttt{F0}, \texttt{TB}, \texttt{TS}, \texttt{senior\_cap}, \texttt{non\_hg\_cap} and \texttt{no\_buy} are $\mu$, $F_0$, $T_B$, $T_S$, $R_{\mathrm{sen}}$, $R_{\mathrm{nhg}}$ and $U$; the variables \texttt{sell}, \texttt{buy}, \texttt{squad}, \texttt{cover} and \texttt{start} are $s$, $b$, $x$, $z$, $y$; and the named constraints are \eqref{eq:linkE}--\eqref{eq:unavailable}. The terms \texttt{a}, \texttt{d} and \texttt{lam} are neutral in every run, and \texttt{omega} is 1 except in the weak-role run, so the base run solves \eqref{eq:objective}.

\subsection{Runnable example}\label{app:example}

The example has eight invented players in three roles (Listings~\ref{lst:toyplayers} and~\ref{lst:toyroles}): \texttt{status} is E (existing) or C (candidate), money is in \pounds m and wages per year, and the last four columns of \texttt{players.csv} are $h_p$, $t_p$, $a_p$ and $d_p$. Listing~\ref{lst:toydriver} sets one starter and squad place per role, no depth reward and wages of at most \pounds 10m, and solves at net allowances of \pounds 40m and \pounds 30m. With the four files in one folder, \texttt{python run\_toy\_example.py} prints Listing~\ref{lst:toyoutput}; it needs Python 3 and \texttt{gurobipy}, whose bundled size-limited licence is enough.
